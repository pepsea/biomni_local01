# 31. 「回答が得られませんでした」で終わらせない

## 症状

```
回答
  回答が得られませんでした。
この結論に至った論点
  ⚠️ 論点がありません。
```

これだけです。ランは「成功」で終わっており、次に何をすればよいのか、
どのモデルに替えればよいのかも分かりません。

## 何が起きていたか

回答が空になるのは、`<solution>` が無く、抽出も `answer` を返さなかった場合です。
`result.answer = trace.solution_text` の逃げ道はありますが、
**`<solution>` 自体が無ければ逃げ先も空**です。

そして、パイプラインは理由を知っていました。

- `result.error` — 探索が例外で止まった
- `trace.steps` が空 — 1 ステップも動いていない
- `trace.stopped_reason` — max_steps / wallclock / 解析エラーで打ち切り
- `trace.parsing_errors` — モデルがタグを出せていない
- `extraction.parse_error` — 抽出応答を読めなかった

知っているのに、画面には出していませんでした。§30 と同じ形の失敗です。
**空の結果を、理由なしで出していた。**

## 直し方

### 1. 本文から拾う

`<solution>` が無いのは、多くの場合モデルがタグを出せていないだけで、
本文（think）には結論らしきものが書かれています。最後のまとまった本文を
拾い、`answer_from: "think"` の印を付けて見せます。

空白の画面より、印の付いた途中の記述のほうが役に立ちます。

### 2. 理由を必ず言う

拾えたときも拾えなかったときも、分かっている事実から理由を書きます。

```
モデルが <solution> を出せませんでした（タグの無い応答を 12 回差し戻し）
エージェントが 34 ステップ動きましたが <solution> を出さずに終わりました
エージェントが 1 ステップも実行できませんでした
探索が例外で止まりました（…）
抽出応答を読めませんでした（…）
```

画面と Markdown レポートの両方に出します。

### 確認

保存済みのランを実ブラウザで開いて確かめました。

```
回答
  回答が得られませんでした。
  ⚠️ モデルが <solution> を出せませんでした（タグの無い応答を 12 回差し戻し）
この結論に至った論点
  ⚠️ 論点がありません（抽出モデルが reasoning を返しませんでした）。
```

## 教訓

**「できませんでした」で終わる表示は、だいたい実装の手抜きです。**
その時点で分かっていることを並べれば、たいてい原因は書けます。
§27（保存先）、§30（論点）、そしてここ。同じ直し方が 3 回続いています。
