# 23. biomni の打ち切りは一度も発動しない

## 23.1 症状

```
34 parsing_error  タグの無い応答を biomni が差し戻しました（28 回目）。
                  … biomni は 2 回まで差し戻し、それでも直らなければ
                  ランを打ち切ります。…
```

**28 回目。** メッセージは「2 回まで」と書いています。矛盾しています。
そして矛盾しているのはメッセージのほう＝§16 で私が書いた説明です。

## 23.2 条件が成立しない（2 つの理由が重なっている）

`biomni/agent/a1.py` の `generate` ノード:

```python
error_count = sum(
    1 for m in state["messages"]
    if isinstance(m, AIMessage) and "There are no tags" in m.content
)
if error_count >= 2:
    state["next_step"] = "end"          # 打ち切り
else:
    state["messages"].append(
        HumanMessage(content="… But there are no tags in the current response. …")
    )
```

| # | 理由 |
|---|---|
| 1 | 差し戻しは **`HumanMessage`** として積まれるのに、条件は **`AIMessage`** しか数えない |
| 2 | 文言は `But there are **t**here are no tags`… 正しくは `But there are no tags`（小文字 t）だが、条件は `**T**here are no tags`（大文字 T）を探している |

実測:

```
差し戻し 5 回積んだあとの error_count = 0
打ち切り条件 (>= 2) を満たすか: False
"There are no tags" in RETRY  →  False
```

**どちらか一方だけでも成立しません。** 打ち切りは死んでいて、
`recursion_limit=500` かこちらの `max_steps` に当たるまで、
同じ失敗を繰り返しながらトークンと時間を消費し続けます。

## 23.3 なぜ気付かなかったか

§16 を書いたとき、私はこのコードを読み、**書いてある意図をそのまま説明として
写しました**。「2 回まで差し戻し、それでも直らなければ打ち切る」と。
**条件が実際に成立するかは試していません。**

§21.18（temperature をスタブで検証していた件）とまったく同じ誤りです。
**コードを読んで分かった気になり、動かして確かめていない。**

読むだけで分かるのは「作者が何をしたかったか」であって、
「何が起きるか」ではありません。

## 23.4 対処: 自前で止める

`TracingRunner` が**連続**の差し戻し回数を数え、3 回で打ち切ります。

- **連続**で数える。1〜2 回は持ち直すことがあり（§16 の
  `test_run_recovers_after_a_retry`）、そこで止めると使えるランを潰す
- タグ付きで返せたら連続カウントを戻す。**通算は戻さない**
  （何回つまずいたかは結果に残す）
- 打ち切ったら `stopped_reason` に理由と対処を入れる

```
差し戻しが 20 回分あっても → 通算 3 回で打ち切り
1 回つまずいて持ち直す     → 打ち切らない（solution まで到達）
```

3 という数字の根拠: 連続 3 回はもう構造的な問題（context 切れ・モデルの
追従性）で、4 回目が通る見込みが無い。1〜2 回は揺らぎの範囲。

## 23.5 メッセージの訂正

「biomni は 2 回まで差し戻し…」を消しました。**効かない安全装置を
『効く』と書くほうが、書かないより悪い**。読んだ人は「じゃあ勝手に
止まるのだろう」と思って放置します。実際は 28 回回り続けます。

原因の列挙も差し替えました。§22 で分かったとおり、いちばん多いのは
**context が尽きてタグの規定が落ちる**ことです。

## 23.6 上流に報告すべきもの

これは biomni 側のバグです（0.0.8 で確認）。
`isinstance(m, AIMessage)` を `HumanMessage` に変え、
文字列比較を大文字小文字無視にすれば直ります。
こちらの対処は、上流が直るまでの防壁として残します。
