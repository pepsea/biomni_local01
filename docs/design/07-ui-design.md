## 7.1 画面構成

### 根拠チップ

各チップは `kind` に応じたアイコンと検証バッジ（✓ 検証済 / − 検証不能 / ⚠ 反証 / ✕ 検証失敗）を持つ。
**クリックで右から根拠ドロワーが開く。**

```
┌── 根拠ドロワー ───────────────────────────────────┐
│ 🗄 gwas_catalog.pkl                    ✓ 検証済    │
│ ライセンス: Apache-2.0                             │
│ 帰属: EBI GWAS Catalog                             │
│ ───────────────────────────────────────────────── │
│ この主張を支える部分                                │
│   「FGFR2 の発現上昇」                             │
│ なぜ                                               │
│   GWAS Catalog で FGFR2 座位が乳がんリスクと強く    │
│   関連する（p=2e-76）                              │
│ ───────────────────────────────────────────────── │
│ 抜粋（実行結果からの原文）                          │
│   rs2981582 | FGFR2 | breast carcinoma | p=2e-76  │
│ ───────────────────────────────────────────────── │
│ 由来: ステップ 5                     [トレースへ →] │
│   実行コード:                                       │
│   ┌───────────────────────────────────────────┐   │
│   │ from biomni.tool.database import ...      │   │
│   │ res = query_gwas_catalog("breast cancer") │   │
│   └───────────────────────────────────────────┘   │
└───────────────────────────────────────────────────┘
```

**「トレースへ →」で該当ステップにジャンプする**のが体験の肝。
仮説 → 根拠 → 実行コード → 生出力、を 2 クリックで辿れること。これが本アプリの存在理由。

● 1 思考   まず GWAS Catalog から乳がん関連座位を取得する
● 2 実行   query_gwas_catalog  [gwas_catalog.pkl]        4.2s  [コード▾]
● 3 観測   rs2981582 FGFR2 ... 128 行                          [出力▾]
● 4 実行   pandas で DepMap と突き合わせ  [DepMap_*.csv]  8.9s

- コード / 出力は既定で折りたたみ。長い出力は先頭 2000 文字＋展開
- ポリシーブロック（⊘）を隠さない。なぜその手が使えなかったかが分かる
- 停止ボタンは常時表示。ローカル LLM は遅く、途中で見切りたい場面が多い

### モデル選択プルダウン

`GET /api/models` の結果をそのまま出す。**ローカルにあるものだけが選択肢**になる。

```
┌ モデル ─────────────────────────────────────────────┐
│ ★ qwen3:14b                  9.3GB  ctx 40,960     │
│      Apache-2.0                                     │
│ ★ qwen3:8b-instruct-q4_K_M   5.2GB  ctx 40,960     │
│      Apache-2.0                                     │
│ ✓ deepseek-r1:7b             4.7GB  ctx 131,072    │
│      MIT · 思考トークンが長い。stop 制御を要検証     │
│ ─────────────────────────────────────────────────  │
│ ✕ llama3.1:8b                4.9GB       グレー表示 │
│      Llama Community License                        │
│      MAU 条項と命名条項があるため既定で不可          │
│ ✕ gemma3:12b                 8.1GB       グレー表示 │
│      Gemma 利用規約 · 利用制限条項                   │
│ ─────────────────────────────────────────────────  │
│ … qwen3:32b                       未取得            │
│      ollama pull qwen3:32b   [コピー]               │
└─────────────────────────────────────────────────────┘
                                          [↻ 再読み込み]
```

原則:

1. **使えないモデルを一覧から消さない。** グレーアウトして理由を併記する。
   消すと「モデルが出てこない」という問い合わせになるだけで、判断材料が残らない
2. **未取得の推奨モデルも出す。** `ollama pull` コマンドをコピーできるようにする
3. `↻ 再読み込み` は `GET /api/models?refresh=true`。`ollama pull` した直後に押す
4. `num_ctx` を手で設定していてモデル上限を超える場合、選択時に
   「40,960 に丸めました」とインラインで出す（黙って変えない）
5. Ollama 未起動なら、プルダウンの代わりに `ollama serve` の案内を出す

## 7.6 デザイン原則

1. **根拠は常に 2 クリック以内**。仮説カード → チップ → 実行コードと生出力。
2. **不確かさを隠さない**。確度・新規性・検証状況・未裏付け・失敗引用をすべて表に出す。
   隠して滑らかにすると、研究用途では逆に信頼を失う。
3. **待ち時間を情報にする**。ローカル LLM は数分かかる。進捗バーではなく、
   実際に何を調べているかをトレースとして流す。
4. **ライセンスは常に見える位置に**。根拠チップ・データタブ・レポートの 3 箇所。
5. **エクスポート第一級**。研究ノート / スライド / 共同研究者への共有が最終目的地。
   Markdown コピーボタンを仮説カード単位でも用意する。
