# 18. 最終回答に「論点」を持たせる

## 18.1 biomni の既定はどうなっているか

`A1._generate_system_prompt()` が `<solution>` について書いているのは、実質これだけです
（`biomni/agent/a1.py:1086`）。

> 2) When you think it is ready, **directly provide a solution** that adheres to the
> required format for the given task to the user. Your solution should be enclosed
> using "\<solution\>" tag, **for example: The answer is \<solution\> A \</solution\>**.

**唯一の記載例が 1 文字の `A`** です。そして:

- 理由を述べよという指示が無い
- 根拠を挙げよという指示が無い
- 構造の指定が無い（見出しも節も無い）

これは手抜きではなく、**biomni がベンチマーク評価のために設計されている**からです。
同梱のタスクは 2 つだけで、どちらも短い答えを自動採点します。

| タスク | 期待する出力 |
|---|---|
| `biomni/task/lab_bench.py` | 多肢選択。`[ANSWER]A[/ANSWER]` の 1 文字。「We require this because we use **automatic parsing**」 |
| `biomni/task/hle.py` | `Question: {question}` のみ。短答 |

`<solution>` は**採点器に食わせる文字列**であって、人に読ませる説明ではありません。
だから既定のまま使うと、どれだけ長く調査しても最終回答は 1〜2 文で出てきます。

「最終回答がシンプルすぎる」のは設定ミスではなく、**上流の設計目標がそもそも違う**ということです。

## 18.2 これまでの状態

このアプリは `<solution>` をそのまま出さず、抽出フェーズ（`biomni_hypo/extractor.py`）で
`answer`（日本語 3〜5 文）+ `answer_evidence`（根拠 ID）に組み直していました。
biomni 既定よりは前進していますが、まだ

```
結論（3〜5 文の平文） + 根拠 ID の一覧
```

でしかありません。**根拠は「どれを見たか」を示すだけで、「それがどう効いたか」は示さない。**
読んだ人は結論を丸ごと受け入れるか、丸ごと捨てるかしか選べません。

## 18.3 決めたこと

回答に **論点（ReasoningPoint）** を持たせます。1 件は次の 4 つ組です。

| 項目 | 中身 | なぜ要るか |
|---|---|---|
| `point` | 検討した論点。**問いの形**（「〜か」） | 何を確かめようとしたのかが分かる |
| `finding` | 調べて実際に分かったこと。数値・遺伝子名を含める | 主張ではなく所見を書かせる |
| `stance` | `supports` / `refutes` / `context` | **結論と食い違う所見を残す場所を作る** |
| `weight` | `decisive` / `supporting` / `weak` | どれが結論を決めたのかが分かる |

加えて `uncertainties`（調べたが分からなかったこと）を必須の枠として置きます。

抽出プロンプトでは `reasoning` を **required** にし、
「結論だけでは不十分です」「都合のよい論点だけを並べてはいけません」と明示します。

### 順序

表示は **反証 → 決め手 → 補強 → 弱い** の順にします。
時系列でも「支持が先」でもありません。**反証を下に押しやると読まれない**からです。

### 根拠が無い論点も残す

`_build_reasoning()` は、未知の eid を落としても**論点そのものは残します**。
「調べたが裏付けられなかった」は情報です。論点ごと捨てると、
**示せなかったという事実が消えて、示せたことだけが残る**という最悪の歪みが出ます。

## 18.4 論点も同じ検証を通す

`pipeline.py` は論点の根拠を `verifier.verify_evidence_list()` に通します。
仮説の根拠・回答の根拠とまったく同じ扱いです。

```python
for point in extraction.answer_reasoning:
    point.evidence = verifier.verify_evidence_list(point.evidence, trace.steps)
```

論点だけ検証を免除すると、**もっともらしい筋道が無検証で通ってしまい**、
§3 の根拠モデル（実行したコードの出力に識別子が現れたか）に穴が開きます。
説明が増えるほど、検証していない説明は危険になります。

## 18.5 論点が出なかったときは黙らない

結論はあるのに `reasoning` が空 = **biomni 既定の「短い答え」に戻っている状態**です。
`extra["reasoning_missing"] = True` を立て、画面とレポートの両方に警告を出します。

抽出モデルの指示追従性が足りないと起きるので、対処は §16 と同じ
（より大きなモデル、または Claude）です。黙って結論だけ出すと、
**説明が無いのか、説明できない結論なのかが区別できません**。

## 18.6 やらないこと

**biomni のシステムプロンプトを書き換えて `<solution>` に構造を要求する**ことはしません。

- A1 のシステムプロンプトは 16k トークン前後あり、追記は context を直接圧迫する（§4.5）
- 探索中のモデルに「調べる」と「説明を構造化する」を同時にやらせると、両方の質が落ちる
- biomni の更新でプロンプトが変わるたびに追従が要る

探索は biomni に任せ、**説明の組み立ては抽出フェーズに分ける**という §3 の分業をそのまま守ります。
抽出は探索の全トレースを見たうえで、根拠 ID を固定した制約下で書くので、
探索中に書かせるより素性がよくなります。
