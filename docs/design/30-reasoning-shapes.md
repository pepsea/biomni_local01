# 30. 「論点を抽出できませんでした」が毎回出る

## 症状

何回やっても、どのモデルを使っても、回答の下にこれが出る。

```
⚠️ 論点を抽出できませんでした。抽出モデルが結論だけを返しています。
```

文言は「モデルのせい」と言っていますが、モデルを替えても直りません。
**替えても直らないなら、モデルのせいではありません。**

## 原因

`_build_reasoning()` が、仕様どおりの形以外を全部捨てていました。

```python
for item in raw or []:
    if not isinstance(item, dict): continue
    point = str(item.get("point", "")).strip()
    if not point: continue
```

`reasoning` の各項目が dict で、キーが厳密に `point` である場合しか通りません。
実際にモデルが返す形を並べて、どれが通るか測りました。

| モデルが返した形 | 直す前 | 直した後 |
|---|---|---|
| `[{"point": …, "finding": …}]`（仕様どおり） | 1 件 | 1 件 |
| `["…か", "…か"]`（文字列の配列） | **0 件** | 2 件 |
| `[{"question": …, "observation": …}]` | **0 件** | 1 件 |
| `[{"claim": …, "detail": …}]` | **0 件** | 1 件 |
| `[{"point": "", "finding": …}]`（所見だけ） | **0 件** | 1 件 |
| `{"point": …}`（配列に入れ忘れ） | **0 件** | 1 件 |
| `{"points": [...]}`（入れ子） | **0 件** | 1 件 |

仕様どおり以外は全滅です。モデルごとに崩し方が違うので、
**どのモデルでも起きます**。症状の説明がこれで付きます。

## 直し方

### 1. 形の揺れを拾う

キー名の候補を持ち、文字列だけ・配列に入っていない・入れ子も受けます。
論点が空で所見だけなら、所見を論点として立てます（捨てるよりまし）。

Ollama では JSON Schema で構造化出力を強制していますが、
Claude 側は入れていないので、プロンプトの守り方に依存します。
**受け側を広くするほうが確実です。**

### 2. 「返さなかった」と「捨てた」を言い分ける

拾えなかった数を数えて残します。

```
抽出モデルが reasoning を返しませんでした
reasoning は 2 件ありましたが、形が想定と違うため使えませんでした
抽出応答を読めませんでした（JSON としてパースできませんでした）
```

画面と Markdown レポートの両方に、この理由をそのまま出します。
一括りの文言に戻すと、また「モデルを替えても直らない」に戻ります。

## 教訓

**受け取る側が厳しすぎると、送り手のせいに見えます。**
「モデルが返していない」と書いた文言が、こちらが捨てている事実を隠していました。
捨てるときは、必ず数を残すこと。
