# 45. 原因を並べず、測って言う

## 症状

```
0 parsing_error  タグの無い応答を biomni が差し戻しました（通算 1 回 / 連続 1 回）。
                 モデルが <execute> / <solution> のどちらも出力しませんでした。
                 よくある原因: (1) context が尽きてタグの規定が落ちている…
```

**ステップ 0 です。** 0 手目にはまだ何も積まれていません。
**context が尽きることはあり得ません。** それを筆頭の原因として挙げていました。

## 何が悪かったか

`PARSE_ERROR_HINT` が固定の文字列で、「よくある原因」を 3 つ並べるだけでした。

```python
PARSE_ERROR_HINT = (
    "…よくある原因: (1) context が尽きて…、(2) num_predict が小さく…、"
    "(3) 指示追従性の低いモデル。…"
)
```

一覧は、書く側には楽です。**読む側には、どれが自分の話なのか分かりません。**
しかも今回のように、その状況ではあり得ないものが先頭に来ます。

こちらは必要な数字を全部持っていました。`num_ctx`、システムプロンプトの
推定トークン数、何手目か、`num_predict`、モデル名 ── **測れるのに測って
いませんでした。**

## 直し方

`parse_error_hint(bundle, step_idx)` にして、場合ごとに測り分けます。

### 1. そもそもプロンプトが入りきっていない

```
システムプロンプトだけで num_ctx の 104% を占めています
（約 17,000 / 16,384 トークン）。**最初から入りきっていません。**
num_ctx を上げるか、ツールモジュールを絞ってください。
```

これは「context が尽きた」とは別の話です。尽きたのではなく、
**最初から入っていない**。対処も違います。

### 2. 早い段階の失敗

```
ステップ 0 での失敗なので、**context 切れではありません**
（まだ何も積まれていません）。指示追従性の問題です。
num_predict=4,096 が小さいと <think> の途中で生成が尽きることもあります。
より指示追従性の高いモデルに替えると直ることが多いです（現在: qwen3:14b）。
```

**排除できる原因は、はっきり排除します。** 3 つのうち 1 つを潰すだけで、
読む側の手間は目に見えて減ります。

### 3. 後半の失敗

```
ステップ 8 時点で約 43,400 / 40,960 トークンを使っています
（1 手あたり約 3,300、埋まるまで約 7 手）。
```

ここで初めて context の話をします。しかも「かもしれない」ではなく、
超えている数字を出します。

## 細かいが大事なこと

- **いま使っているモデルを勧め返さない。** `qwen3:14b` で動かしている人に
  「qwen3:14b 以上を試してください」は助言になっていません。
  現在のモデル名を出し、「より指示追従性の高いものへ」と書きます。
- **分からない数字は書かない。** 推定トークン数が取れないとき、
  「約 0 トークン」と出していました。「まだ何も積まれていません」に変えました。

## テストの書き方も変えた

古いテストは `assert "num_ctx" in text` でした。文言が測った内容で変わるので、
この書き方では正しい変更でも落ちます。**性質で見る**ようにしました。

```python
assert "差し戻し" in text
assert "ステップ" in text, "どこで起きたかが無い"
assert ("モデル" in text) or ("num_ctx" in text), "次の一手が無い"
```

何が起きたか・どこで起きたか・次に何をするか。この 3 つが入っていればよい。

## 教訓

**「よくある原因」の一覧は、調べていないことの言い換えです。**
数字を持っているなら、一覧ではなく判定を出すこと。
このセッションで §27・§31・§33・§36 と繰り返してきた形が、
助言の文面そのものにも当てはまりました。
