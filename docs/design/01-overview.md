# 01. 概要 — 目的・スコープ・要件

## 1.1 何を作るか

研究者が自然言語で研究課題を入力すると、Biomni エージェントが調査を実行し、
**検証可能な仮説** と **その仮説を支える根拠** をセットで返す Web アプリ。

```
入力: 「トリプルネガティブ乳がんで PARP 阻害剤耐性を規定する因子の候補は？」
   ↓
出力: 仮説カード × N
      ├─ 仮説文（1文、検証可能な形）
      ├─ 根拠（使用データセット / 文献 / DB レコード / 実行した解析）← 本アプリの主目的
      ├─ 前提と反証データ
      └─ 検証実験プラン（実験系・読み出し・対照）
      + 全実行トレース（生成コード・出力・図）
```

**「使用したデータとその根拠を示す」ことを第一級の出力とする。**
仮説文だけを返すのは要件未達とみなす。根拠のない主張は「未裏付け」として区別して表示する。

## 1.2 なぜ Biomni か

Biomni（Stanford SNAP）は生物医学特化の汎用エージェント。本アプリが自前で作らずに済む部分：

- **ツール群**: `biomni/tool/` 配下に約 30 モジュール、公共 DB クエリ（UniProt / Ensembl / OpenTargets / ClinVar / GWAS Catalog / STRING / Reactome / cBioPortal / gnomAD / ChEMBL / PubChem など約 50 種）と文献検索（PubMed / arXiv / Scholar）を関数として提供。
- **データレイク**: S3 配布のキュレート済みデータセット群（`biomni/env_desc.py` に名前と説明）。
- **実行ループ**: LangGraph ベースの ReAct ループ。LLM が `<execute>` タグ内に Python / R / Bash を書き、実行結果が `<observation>` として戻る。最終回答は `<solution>`。
- **リソース検索**: クエリに応じてツール・データ・ライブラリ・ノウハウ文書を LLM で選択（`use_tool_retriever`）。

**本アプリが上乗せする価値**は次の 4 点で、これは Biomni 標準の Gradio デモ（`A1.launch_gradio_demo`）には無い：

1. 実行トレースからの**根拠抽出と構造化**（どのデータのどの行が、どの主張を支えるか）
2. 引用の**実在検証**（PMID・アクセッション・ファイルパスが実在するかを機械的に確認）
3. 仮説単位での**永続化・比較・エクスポート**
4. **商用利用ポリシーの強制**とライセンス表記の自動生成（Biomni の `commercial_mode` はデータセットを絞るだけで、ツールは絞らない）

## 1.3 スコープ

### v1 に含む

- 単一の研究課題を入力 → 仮説リスト＋根拠を出力する 1 ラン完結のフロー
- Ollama によるローカル LLM 実行
- 実行トレースのライブ表示（SSE）とラン履歴の保存
- 根拠の抽出・検証・可視化
- ユーザー自前データ（CSV / TSV）のアップロードと解析対象への組み込み
- Markdown / JSON でのレポートエクスポート

### v1 に含まない（意図的に外す）

- マルチユーザー・認証・権限管理（単一ユーザーのローカル運用前提）
- 仮説の自動実験実行・ロボット連携（Biomni の `lab_automation` ツールは対象外）
- 患者個人データ・臨床データの取り扱い（**設計上、非識別化済みの公開データのみを前提**）
- クラウド LLM（Anthropic / OpenAI）— ただし差し替え可能な形にはする（§04 参照）
- **非商用ライセンスのデータ・モデル・ライブラリ**（§05 の方針により恒久的に対象外。設定で有効化することもできない）

## 1.4 主要ユースケース

| ID | ユースケース | 成功条件 |
| --- | --- | --- |
| UC-1 | 疾患・表現型から候補遺伝子/経路の仮説を得る | 各仮説に DB レコードまたは文献の根拠が 1 件以上付く |
| UC-2 | 自分の発現データ（CSV）を投げて解釈仮説を得る | 仮説の根拠にアップロードしたファイルの具体的な行・統計量が引用される |
| UC-3 | 既存仮説の裏付け・反証を集める | 支持根拠と反証根拠が分けて提示される |
| UC-4 | 出てきた仮説を実験計画に落とす | 実験系・読み出し・対照を含む検証プランが付く |
| UC-5 | 結果を共有・監査する | 生成コードと出力を含むレポートを出力でき、第三者が再現手順を追える |

## 1.5 非機能要件

| 項目 | 目標 | 備考 |
| --- | --- | --- |
| 実行環境 | ローカル 1 台（Linux / macOS）。GPU 任意 | Ollama が動けばよい |
| 応答性 | 1 ラン 3〜15 分。最初のトレースイベントは 30 秒以内に届く | ローカル LLM の生成速度が支配的 |
| 並行実行 | v1 は同時 1 ラン（キューイング） | A1 インスタンスはステートフル。§02 参照 |
| データ主権 | 質問文と自前データはローカルに留まる。外部送信は公共 DB 問い合わせ時のみ、かつ UI で明示 | オフラインモードで外部問い合わせを完全遮断できる |
| 再現性 | ランごとにモデル名・温度・Biomni バージョン・ツール一覧・全コードを保存 | 「同じ答え」ではなく「同じ手順を追える」ことを保証 |
| 安全性 | LLM 生成コードはコンテナ内で実行、タイムアウト必須 | §02.6 参照 |
| **商用利用適合** | 使用するデータ・モデル重み・ライブラリ・外部 API がすべて商用利用可能であること。既定拒否で強制する | §05 参照。`A1(commercial_mode=True)` は前提だが不十分 |

## 1.6 用語

| 用語 | 定義 |
| --- | --- |
| **Run（ラン）** | 1 つの研究課題に対する 1 回のエージェント実行。 |
| **Step（ステップ）** | ラン内の 1 手（思考 / コード実行 / 観測 / 最終回答）。 |
| **Hypothesis（仮説）** | ランから抽出された、検証可能な 1 つの主張。 |
| **Evidence（根拠）** | 仮説を支持/反証する具体物。必ず Step と Resource に紐付く。 |
| **Resource（リソース）** | 根拠の出所。データセット / ツール / 文献 / DB レコード / 計算結果のいずれか。 |
| **Provenance（来歴）** | 「どの Resource を、どの Step で、どう使って、どの主張に至ったか」の連鎖。 |
