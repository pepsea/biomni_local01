# 32. 同じ Ollama を他のツールと共有する

## 質問

「他のツールで Ollama を使っていると、回答が空になりますか？」

## 答え

**なりえます。ただし直接の原因ではなく、遅くなった結果としてです。**

Ollama は 1 台のサーバをすべてのクライアントで共有します。別のツールが
同じ Ollama を使っていると、次の 3 つが起きます。

1. **メモリの取り合い** — 2 つのモデルが同時に載ると、VRAM に収まらない分は
   CPU 側に溢れます。生成速度が数倍から数十倍落ちます。
2. **読み込み直し** — 載せられるモデル数を超えると、切り替えのたびに
   アンロードとロードが入ります。大きいモデルでは 1 回で数十秒かかります。
3. **順番待ち** — 同じモデルへの同時要求は、並列数を超えると待たされます。

このアプリのランは複数ステップの連続で、各ステップが 1 回の生成です。
1 ステップが遅くなれば、その分だけ全体が伸びます。そして
`wallclock_limit` や `max_steps` に当たると、`<solution>` に到達する前に
打ち切られます。結果は `<solution>` 無し、つまり
**「回答が得られませんでした」** です。

つまり因果はこうです。

```
他のツールと共有 → 遅くなる → 打ち切られる → <solution> が無い → 回答が空
```

## 見分け方

§31 の修正が入っていれば、画面に理由が出ます。**理由で切り分けてください。**

| 画面に出る理由 | 取り合いが原因か |
|---|---|
| `wallclock_limit(…s) に到達` | **その可能性が高い** |
| `max_steps(…) に到達` | 可能性あり（1 ステップが遅く、進みが浅い） |
| `タグの無い応答を N 回差し戻し` | 違う。モデルの指示追従性の問題（§24） |
| `1 ステップも実行できませんでした` | 違う。依存かエージェントの構築の問題 |

## 確かめる

`bash scripts/diagnose-ollama.sh` に、いま読み込まれているモデルを出す節を
足しました（`/api/ps`）。

```
== 3. いま Ollama に読み込まれているモデル
      gemma3:27b
      qwen3:14b
  ! このアプリが使う qwen3:14b 以外も読み込まれています: gemma3:27b
      同じ Ollama を他のツールと共有すると、こうなります:
        - メモリを取り合い、層が CPU に溢れて生成が数倍〜数十倍遅くなる
        …
```

手元でも `ollama ps` で同じことが見えます。

## 実装上の注意

- `keep_alive="30m"` を指定しています。ランの途中でモデルが降りて
  読み込み直しになるのを防ぐためです。他のツールが別のモデルを要求すると、
  それでも降ろされることがあります。
- `/api/ps` の JSON は、コロンの後ろの空白の有無が実装によって変わります。
  空白なしを前提に書いたら 0 件に見えました（実測で踏んだ）。
  テストは空白あり・なしの両方を通しています。
